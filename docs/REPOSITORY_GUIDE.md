# Repository guide

This repository is a frozen chronological research record. Files remain at the root because builders and notebooks refer to their historical names. Use this guide as the task-oriented index.

## Reading order

1. `README.md` - scope, final conclusion, and public-release boundary.
2. `docs/FINAL_STATUS.md` - evidence hierarchy and prohibited interpretations.
3. `DATA_USE.md` - access requirements before touching data.
4. `ROADMAP_updated.md` - frozen prespecification and project phases.
5. `OpenOx_Project_Hub.md` - detailed decisions D001-D036.

## Analysis chronology

| Stage | Notebooks | Purpose |
|---|---|---|
| Pairing and feasibility | 01b-04 | Pair construction, timing sensitivity, endpoints, device harmonization, repeated measures |
| Prespecification | 05-06, 07b | Pigmentation/context locks and workflow audit |
| Core analyses | 07, 07c, 08-10 | Device, occult-hypoxemia, pigmentation, and perfusion/context analyses |
| Prediction lock and internal validation | 11, 11b, 12-19 | Target, grouped resampling, compact model, safeguards, subgroup/enrichment tests, final lock |
| External evidence | 20-23 | BOLD raw transfer, ENCoDE partial replication, SpO2-only diagnostic, bounded BOLD updating |

Notebook 17 was generated by `build_17_prediction_enrichment_blocks.py` but is not part of the reviewed public notebook set. Its aggregate decision record is retained in the hub; restricted outputs remain private.

## File roles

- `build_*.py`: deterministic notebook/workflow construction scripts.
- analysis scripts such as `bold_external_validation.py`: substantive calculations against authorized local inputs.
- `qa_*.py`: independent late-stage checks.
- `src/config.py`: local OpenOximetry path validation and output directories.
- `release_check.py`: fail-closed public-release scanner and manifest generator.

## What cannot be public

The public tree is not a data bundle and not a precomputed-results archive. Full execution requires separately authorized PhysioNet files and locally generated restricted intermediates. Expected hashes in scripts identify the exact analyzed source releases; they do not grant access or permission to redistribute them.
